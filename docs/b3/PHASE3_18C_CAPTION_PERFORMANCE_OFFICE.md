# Office caption and reader-performance continuation

Base candidate: `054167f189749fe6f05444f349e4364f726fd232`, build `qdIBVgViBZX1Se2M4SiUD`, draft PR #58. This separate continuation retains the September QA issue, publications, protected media/tombstones and prior acceptance evidence.

The standard public video contract already supplies `captionUrl` and CMS accessibility metadata. The standard reader's feed/deep-link mappings dropped it, and the shared HTML video player rendered no track. Caption URL/language now pass through those existing mappings to the shared player, which uses a native WebVTT track, anonymous CORS when captioned, the existing caption-state callback and a labelled keyboard-operable control. Native track-state changes synchronize the control. Uncaptioned videos keep their prior media/CORS behavior. Existing accessibility language metadata is used, with the existing Hindi default when absent.

Caption acceptance must operate the actual application directly on provider-allowed `http://localhost:3000`; no origin proxy, successful-response mock or provider policy change is used. That office-origin result does not certify any untested staging/deployment origin. The generated MP4/VTT pair is retained unchanged. One labelled uncaptioned QA publication reuses that MP4 without mutating existing publications or creating provider objects.

Repeated baseline monthly traces reproduce the interaction and layout failures. Initial page dimensions were unused by the canvas; a ResizeObserver updated React fitting state after first paint; desktop spread initialization replaced a single-page layout later; the shell removed its header/footer and changed container geometry after the reader opened. Image dimensions now reserve geometry, CSS container sizing and responsive spread rules fit pages before hydration, and the hidden shell retains geometry while becoming inert. Store subscriptions are scoped to fields consumed by the shell. Zoom/pan coordinates remain imperative, with resize reclamping; page order, history/deep links, controls, hotspots and reduced motion retain their existing seams.

All repeated measurements, including slow first samples and intermediate failures, are retained automatically under `artifacts/phase3-qa/phase318c-office-20261013/caption-performance-20261014/`. Same-content desktop1440×900 CPU1/unthrottled and mobile390×844 CPU4/150ms/1.6Mbps down/0.75Mbps up conditions use cold browser cache and identical interactions. Chrome traces and persisted Web Vitals accompany the runs. Preliminary Playwright DOM snapshot recording measurably distorted interactions; those diagnostic runs remain separate, and comparable runs disable that recorder. Lab measurements are not production field percentiles.

Physical device, screen-reader, browser UI zoom, live transaction/crash checks and production field monitoring remain NOT RUN unless a later evidence packet genuinely executes them. No production access, deployment, migration, domain or cloud-permission changes are authorized. The continuation PR must remain draft and unmerged.
